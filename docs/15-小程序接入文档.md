# 小程序接入文档

**适用对象**：小程序、H5、Taro 等受试者端前端  
**接入服务**：collection-server  
**契约基线**：答卷可靠受理方案 B（2026-07-18）

本文是小程序接入的现行入口。报告等待机制的容量、WebSocket 和降级细节见 [12-小程序报告等待接入指南.md](./12-小程序报告等待接入指南.md)。

---

## 1. 接入结论

小程序主流程固定为：

```text
开始会话
  → 请求前落盘 fingerprint + idempotency_key + request_id
  → 提交答卷（HTTP 202 accepted + answersheet_id）
  → 按 answersheet_id 查询 assessment-readiness
  → pending 继续轮询；ready 取得 assessment_id
  → no_assessment_required 跳回答卷详情；failed 显示明确失败
  → 优先订阅 WebSocket 报告状态（失败后短轮询）
  → status=interpreted 后读取报告
```

前端必须按以下契约更新：

| 项目 | 当前契约 |
| ---- | -------- |
| HTTP 服务 | collection-server，业务前缀 `/api/v1` |
| 人格产品 URL | 使用 `/typology-*`，不再使用 `/personality-*` |
| 人格目录身份 | `kind=typology`、`product_channel=typology` |
| 测评/报告兼容身份 | `model.kind=personality`；WebSocket `subscribe.kind=personality` |
| 提交结果 | `POST /answersheets` 只有在 AnswerSheet + 幂等记录 + Outbox 提交后返回 `accepted + answersheet_id` |
| Assessment 就绪 | `GET /answersheets/{id}/assessment-readiness?testee_id=...` 返回 `pending`、`ready + assessment_id`、`no_assessment_required` 或 `failed` |
| 报告完成判断 | 以 `report-status.status=interpreted` 为准，不以 Assessment 的内部状态为准 |
| ID 类型 | 所有 64 位 ID 在 TypeScript 中按 `string` 保存和比较 |

> `typology-assessment-sessions.endpoints.assessment_readiness` 是获取 Assessment 就绪状态的唯一 session 模板。

## 2. 服务、鉴权与响应包络

### 2.1 地址

| 环境 | 示例 |
| ---- | ---- |
| 本地 | `http://localhost:18083/api/v1` |
| 生产 | `https://collect.fangcunmount.cn/api/v1` |
| OpenAPI | `GET /api/rest/collection.yaml` |
| Swagger UI | `/swagger-ui/` |

除下列目录接口外，业务接口都需要：

```http
Authorization: Bearer <IAM JWT>
```

可匿名访问的只读接口：

```text
GET /api/v1/assessment-models
GET /api/v1/assessment-models/hot
GET /api/v1/assessment-models/options
GET /api/v1/typology-models
GET /api/v1/typology-models/categories
```

医学量表目录使用 `kind=scale`；选择分类时，传递
`GET /api/v1/assessment-models?kind=scale&category=<category>`。`category`
必须使用 `/assessment-models/options?kind=scale` 返回的 `categories[].value`；不传时查询全部分类。

`GET /assessment-models/{code}`、`GET /typology-models/{code}`、会话、答卷、测评和报告接口仍需登录。

### 2.2 通用响应

成功：

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

失败：

```json
{
  "code": 112001,
  "message": "Assessment not found",
  "reference": ""
}
```

前端应同时判断 HTTP 状态码与 `code`；只有 `2xx && code === 0` 才进入成功分支。

## 3. 人格测评完整流程

### 3.1 开始会话

```http
POST /api/v1/typology-assessment-sessions
Content-Type: application/json
```

```json
{
  "model_code": "MBTI_OEJTS",
  "testee_id": "618855887087350318"
}
```

响应 `data`：

| 字段 | 用法 |
| ---- | ---- |
| `model` | 当前已发布模型摘要 |
| `questionnaire` | 与模型绑定的精确题版和题目 |
| `submit_contract` | 提交答卷时必须原样带回的问卷编码、版本、受试者 ID |
| `endpoints.submit_answer_sheet` | 提交地址 |
| `endpoints.wait_report` | legacy 长轮询模板 |
| `endpoints.report` | 报告地址模板 |
| `endpoints.assessment_readiness` | 按 AnswerSheet ID 查询 readiness 四状态 |

会话只聚合读取已发布模型与问卷，不创建 Assessment。不要缓存“最新问卷版本”替换 `submit_contract.questionnaire_version`。

### 3.2 提交答卷

```http
POST /api/v1/answersheets
Authorization: Bearer <token>
X-Request-Id: <uuid>
Content-Type: application/json
```

```json
{
  "questionnaire_code": "MBTI_OEJTS",
  "questionnaire_version": "1.0.0",
  "testee_id": "618855887087350318",
  "idempotency_key": "mp-MBTI_OEJTS-618855887087350318-20260712-001",
  "answers": [
    {
      "question_code": "Q1",
      "question_type": "Radio",
      "score": 1,
      "value": "{\"option\":\"A\"}"
    }
  ]
}
```

注意：

- `testee_id` 请求端可传字符串或数字，建议始终传字符串。
- `value` 是 JSON 字符串，不是任意嵌套对象。
- `questionnaire_code`、`questionnaire_version`、`testee_id` 取自 session 的 `submit_contract`。
- 重试同一次业务提交时复用同一个 `idempotency_key`；一次新的作答使用新 key。
- `idempotency_key` 必填，只允许 8–128 个安全字符；同一填写人的同键异内容返回 409。
- 建议显式传 `X-Request-Id`，它只跟踪本次 HTTP，不替代幂等键。
- 必须先持久化 fingerprint、`idempotency_key` 和 `request_id`，再发 HTTP。
- fingerprint 使用版本化 `v2:SHA-256`；只用于客户端判断是否为同一作答快照，不代替服务端幂等指纹。
- 每次 HTTP 尝试生成新的 `request_id` 并在发送前落盘；网络重试和进程恢复只复用 `idempotency_key`。

成功受理返回 HTTP 202：

```json
{
  "code": 0,
  "message": "accepted",
  "data": {
    "status": "accepted",
    "request_id": "8bde6a9f-2c3e-4ee8-bb8d-64d48e5b6762",
    "answersheet_id": "71001"
  }
}
```

HTTP 202 表示答卷已可靠受理，前端必须立即落盘 `answersheet_id`。它不表示 Assessment 或报告已完成。

### 3.3 查询 Assessment readiness

```http
GET /api/v1/answersheets/71001/assessment-readiness?testee_id=618855887087350318
```

等待响应：

```json
{"code":0,"message":"success","data":{"status":"pending","answersheet_id":"71001","next_poll_after_ms":2000}}
```

就绪响应：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "status": "ready",
    "answersheet_id": "71001",
    "assessment_id": "80001"
  }
}
```

`pending` 不是提交失败。按 `next_poll_after_ms` 轮询；超过 60 秒展示“答卷已接收，测评生成延迟”。`ready` 必须带真实 `assessment_id`，随后才能调用报告接口。`no_assessment_required` 是独立问卷正常终态，应清理提交上下文并跳回答卷详情；`failed` 应停止自动轮询、展示 `reason/message`，且不得调用报告接口。未知状态以及 `ready` 缺少 ID 都按协议错误处理。`404` 表示答卷不存在，`403` 表示当前用户的 ProfileLink 不允许，依赖异常返回 `503`。

### 3.4 查询报告状态

报告等待默认先尝试 WebSocket；连接不可用、断连、首状态超时或服务端错误后，再按下列接口短轮询：

```http
GET /api/v1/typology-assessments/{assessment_id}/report-status?testee_id={testee_id}
```

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "status": "processing",
    "stage": "interpreting",
    "message": "报告生成中",
    "next_poll_after_ms": 3000,
    "updated_at": 1783785600
  }
}
```

前端状态机：

| `status` | 行为 |
| -------- | ---- |
| `processing` | 按 `next_poll_after_ms` 继续轮询；具体阶段看 `stage` |
| `interpreted` | 停止轮询，读取报告 |
| `failed` | 停止轮询，展示 `reason` |

`stage` 用于提示 `queued / processing / scoring / interpreting` 等内部阶段，不作为终态判断。服务端会把内部兼容值 `completed` 对外归一化为 `interpreted`。

优先连接 `WSS /api/v1/report-events`，订阅帧仍使用 `kind=personality`：

```json
{
  "op": "subscribe",
  "assessment_id": "80001",
  "kind": "personality",
  "testee_id": "618855887087350318"
}
```

WebSocket 只有在服务端启用 `report_events` 时存在。前端首次等待仍应尝试连接；断线、超时或未启用时必须关闭连接后降级到 `report-status`，不得并发双跑。

### 3.5 读取报告

仅在状态为 `interpreted` 后调用：

```http
GET /api/v1/typology-assessments/{assessment_id}/report?testee_id={testee_id}
```

核心响应：

```json
{
  "assessment_id": "80001",
  "model": {
    "kind": "personality",
    "sub_kind": "typology",
    "code": "MBTI_OEJTS",
    "version": "1.0.0",
    "title": "MBTI 人格类型测评",
    "product_channel": "typology",
    "algorithm_family": "factor_classification"
  },
  "primary_score": null,
  "level": { "code": "INTJ", "label": "建筑师" },
  "conclusion": "...",
  "dimensions": [],
  "suggestions": [],
  "model_extra": {
    "type_code": "INTJ",
    "type_name": "建筑师",
    "one_liner": "...",
    "image_url": "https://...",
    "rarity": { "percent": 2.1, "label": "较少见", "one_in_x": 48 }
  },
  "created_at": "2026-07-12 12:00:00"
}
```

展示建议：

- 人格主结果优先使用 `model_extra.type_code/type_name/one_liner`，再回退到 `level`。
- 通用结果使用 `primary_score`、`level`、`dimensions`、`suggestions`。
- 不要用 `algorithm` 判断页面类型；产品分流使用 URL 上下文或 `model.product_channel`，具体模型使用 `model.code`。
- `model_extra`、`primary_score`、`level` 都可能为空，类型定义必须可选。

## 4. TypeScript 最小类型与状态机

```ts
type Id = string;

interface SubmitAccepted {
  status: 'accepted';
  request_id: string;
  answersheet_id: Id;
}

interface AssessmentReadiness {
  status: 'pending' | 'ready' | 'no_assessment_required' | 'failed';
  answersheet_id: Id;
  assessment_id?: Id;
  reason?: string;
  message?: string;
  next_poll_after_ms?: number;
}

interface ReportStatus {
  status: 'processing' | 'interpreted' | 'failed';
  stage?: string;
  message?: string;
  reason?: string;
  next_poll_after_ms?: number;
  updated_at: number;
}

function assertAccepted(value: SubmitAccepted) {
  if (value.status !== 'accepted' || !value.answersheet_id) {
    throw new Error('durable submit contract violation');
  }
}
```

建议页面状态：

```text
idle
  → loading_session
  → answering
  → submit_prepared
  → answersheet_accepted
  → assessment_pending
  → assessment_ready
  → report_processing
  → report_ready | failed

assessment_pending 也可能进入：
  → no_assessment_required（跳回答卷详情）
  → assessment_failed（不调用报告接口）
```

本地恢复至少保存：`fingerprint`、`idempotency_key`、`request_id`、`model_code`、`testee_id`、`answersheet_id`、`assessment_id`。

## 5. 禁止继续调用的旧契约

```text
/api/v1/personality-*
/api/v1/answersheets/{id}/assessment
/api/v1/answersheets/submit-status
/api/v2/assessments*
```

不得调用已删除的 AnswerSheet→Assessment 旧接口，也不得通过 Assessment 列表按 `answer_sheet_id` 匹配作为新提交兜底。唯一正常路径是 `assessment-readiness`。

## 6. 联调验收清单

- [ ] 所有 64 位 ID 在 TypeScript 中使用 `string`
- [ ] session 返回的题版与 submit 使用的版本完全一致
- [ ] HTTP 请求前已落盘 fingerprint、幂等键和 request ID
- [ ] POST 答卷返回 202 后立即保存 `answersheet_id`
- [ ] 网络超时、429、503 重试复用同一幂等键；409 不自动重试
- [ ] 只对 readiness `pending` 按 `next_poll_after_ms` 轮询，`ready` 后保存真实 `assessment_id`
- [ ] `no_assessment_required` 跳回答卷详情；`failed` 展示原因且不调用报告接口
- [ ] 未知 readiness 或 `ready` 缺少 `assessment_id` 按协议错误处理
- [ ] session 使用 `assessment_readiness` 模板
- [ ] 报告轮询按 `next_poll_after_ms` 退避
- [ ] 仅在 `interpreted` 后读取报告
- [ ] 所有报告请求携带同一个 `testee_id`
- [ ] WebSocket 默认尝试且使用 `kind=personality`，失败后具备 HTTP 降级
- [ ] 404 不重试读取他人报告；429 采用指数退避

## Participant AI 补充解读（2026-09-05 接入）

医学标准报告概览后挂载可选入口，详情页为 `/pages/assessment/ai-explanation/index?aid=...&t=...&gid=...`。
入口与详情进入/显示/刷新只查询；用户在准备页点击“开始解读”才发 POST。人格与行为能力暂不挂载入口。
所有 ID 都是字符串；AI 使用已加载报告的 assessment/testee 上下文，不能替换为当前全局选择的受试者。

| 操作 | Collection API（host 已含 /api/v1） | 参数 |
|---|---|---|
| 查询能力 | GET /assessments/{id}/ai-explanation/capability | testee_id、locale=zh-CN |
| 主动请求 | POST /assessments/{id}/ai-explanations | query testee_id，body `{ "locale": "zh-CN", "focus_areas": [] }` |
| 查询已知任务 | GET /assessments/{id}/ai-explanations/{generation_id} | testee_id |

响应按 `{code,data,message}` 解包；POST 200 可直接获得成品，202 只表示 pending/generating。
只展示 `ai-explanation-output/v1` 的完整 content（summary、integrated_insights、suggestions、limitations）。
Collection Go DTO 的 `source_suggestion_refs` 在空序列时为 null，仅 generated_low_risk 可规范化为空数组；缺失字段或 standard_derived 缺少引用仍拒绝展示。
所有内容使用普通 Text，不执行 HTML/Markdown，不按当前报告数组位置伪造引用跳转。

请求明确选择 retry429=false、refreshOnForbidden=false、metadata_only 日志、非交互式鉴权、15 秒超时与生命周期取消。
AI 403 是权限不足，不刷新 token 或退出整个会话；401 仍执行有界认证刷新，重放前必须验证页面/账号未变。
429 立即返回并保留 Retry-After，不安排隐藏 POST 重试。failed.retryable 不授权前端业务重试；“刷新状态”只 GET。

详情页单独负责串行 GET 轮询，约 2/5/10 秒退避，最多前台连续等待 5 分钟；网络恢复最多连续 3 次。
隐藏/卸载/账号或路由上下文改变即取消请求与定时器，晚到响应不进入 UI 或本地指针；显示时重新 GET。
source_state=current/stale/unavailable/unknown 独立展示，旧版本内容不得标为当前标准报告结论。

本地仅保存账号、受试者、测评、gid、来源报告 ID 和过期时间等恢复指针（最多 30 条、7 天）；退出会话删除，不存 AI 正文或 token。429 的 Retry-After 时间戳另按同一身份范围保存（最多 30 条、到期失效），避免退出页面后提前重复请求。
服务端目前没有按当前请求只读查找 gid 的接口；指针丢失或换设备不能自动找回，POST 结果未知时需用户明确再次请求。

插图位于 assessment 分包路径，352×352 WebP 13,730 B。默认静态；用户可开启轻量等待动效或选择减少动画。无虚构进度或自动完成动画。
本地验证结果与剩余真机/联调事项见 [AI 解读设计与实施记录](design/AI-EXPLANATION-DESIGN.md)。
